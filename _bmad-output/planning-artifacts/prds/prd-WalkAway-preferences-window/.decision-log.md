# Decision log — Preferences window appears

Created: 2026-08-31
Status: final

## 2026-08-31 — Fast path

- **Decision:** Same panel activation as SnappyZones: switch to `.regular`, show the window, return to `.accessory` when no keyable panel remains. Present on the next run loop so the status menu can dismiss.
- **Source:** Ferenc, 2026-08-31: Preferences click does not open any window.
- **Landed in:** FR-1–FR-3.

## 2026-08-31 — Delay after policy change

- **Decision:** `setActivationPolicy(.regular)` is asynchronous on current macOS. Present 0.25s later with `orderFrontRegardless()` and `.moveToActiveSpace`. Do not activate during the status-menu click. About uses the same path (not `.floating` alone).
- **Source:** Ferenc, 2026-08-31: 0.1.2 still opens no window. Installed copy was 0.1.2.
- **Landed in:** FR-1, FR-2, `PanelActivation`.

## 2026-08-31 — Off-screen frame

- **Decision:** Do not use `center()`. Place the panel on the screen under the pointer, clamped to `visibleFrame`. Open the panel after `menuDidClose`, not during menu tracking.
- **Source:** Ferenc, 2026-08-31: 0.1.3 still no window. A WalkAway window existed at x=2350, not on-screen.
- **Landed in:** FR-1, FR-2, `PanelPlacement`.
